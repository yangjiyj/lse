# 框架覆盖矩阵

框架覆盖矩阵回答一个问题：**每条风险标准，你测了没有、测出了什么，平台能不能测。**
页面入口：「报告中心 → 框架覆盖」（`/reports/framework-coverage`）；任务详情页有「查看框架覆盖」入口，会带 `taskId` 进入单任务视图。
接口：`GET /api/frameworks/coverage?framework=&taskId=&targetId=&days=`（权限 `eval_task:read`）。

> 未测试不等于安全。覆盖矩阵按平台风险域的参考映射统计，不是认证结论；「已测·未发现风险」只代表本次所测题目未发现问题。

## 1. 覆盖哪些框架

| 框架 | 条目 | 说明 |
| --- | --- | --- |
| OWASP 智能体十大风险 | ASI01–ASI10 | OWASP Top 10 for Agentic Applications（2025-12） |
| OWASP 大模型十大风险 | LLM01–LLM10 | OWASP Top 10 for LLM Applications（2025） |
| 国标附录 A | A.1–A.5 | GB/T 45654-2025 附录 A「训练数据及生成内容的主要安全风险」5 类 |
| MITRE ATLAS | 平台可映射的技术 | 只展示 `RISK_DOMAIN_ATLAS_TECHNIQUES` 里出现的技术（当前 7 条），不展示完整矩阵 |

## 2. 一道题 / 一个结果如何归到框架条目

**不新增映射表，只复用既有映射**：

1. 取已判定结果（`EvalResult.finalVerdict` 为 PASS、FAIL、UNKNOWN；ERROR 与未判定不计入「已测」）。
2. 确定该结果的风险域：题目自身类别 `Question.category`，加上该结果下各 `Finding.riskCategory`，都经 `reports/labels.ts` 的 `riskDomainForCategory` 归一为风险域，取并集；只有 `general_safety` 以外别无他域时才保留 `general_safety`。
3. 风险域 → 条目，全部复用现有映射：
   - OWASP 大模型、国标附录 A：`reports/compliance-mapping.ts` 的 `COMPLIANCE_MAP[域].owasp / .gbt45654`；
   - MITRE ATLAS：`frameworks/index.ts` 的 `RISK_DOMAIN_ATLAS_TECHNIQUES`（只用技术级映射，不用战术级，避免一个域展开成几十个技术）；
   - OWASP 智能体：`COMPLIANCE_MAP[域].agentic` 只存中文威胁名，`coverage.ts` 里用一张小适配表把威胁名换成 ASI 编号（工具滥用→ASI02，权限提升/越权→ASI03，非预期代码执行→ASI05，记忆/知识库投毒→ASI06，意图篡改→ASI01 等）。
   - 平台应用评估的题目带有场景标签（如 `indirect_url`），其智能体威胁取自 `PLATFORM_APP_COMPLIANCE`。
   - 沙箱 L8 的四个场景带 `agent-scenario:xxx` 标签，经 `coverage.ts` 的 `SANDBOX_SCENARIO_THREATS` 映射：目标劫持 → ASI01，记忆投毒 → ASI06，级联故障 → ASI08，越权调用高权限工具 → ASI03。
   - 身份标识、高风险操作人工介入两类场景没有对应的 OWASP 条目，不硬映射；它们归国内标准的智能体 8 项要求（见 `docs/standards/README.md`）。
4. **一个结果映射到多个条目时，在每个条目各计一次**（例如数据外传类题目同时计入 LLM02、LLM06、A.4、ASI02、AML.T0086），所以各条目「已测题数」相加会大于总题数。同一结果经多个风险域映射到同一条目时只计一次。
5. 没有映射到任何条目的已判定题目（如通用安全类、类别缺失）单独汇总为「未映射题数」，不计入任何条目。
6. 「已测题数」的单位是已判定结果数（一道题对一个评估对象执行一次算一条）。
7. 发现项上的人工框架映射（`/findings/:id/mappings`）只作用于热力图，不影响覆盖矩阵。

### 范围
- `taskId`：单个任务；
- `targetId` + `days`：某评估对象在最近 N 天内创建的全部任务；
- 都不传：全平台。

## 3. 状态规则

| 状态 | 条件 | 页面徽章 |
| --- | --- | --- |
| `NOT_SUPPORTED` | 平台没有任何测试能力映射到该条目（且未测到任何题） | 平台暂不覆盖（虚线灰） |
| `NOT_TESTED` | 平台能测，但所选范围内已测题数为 0 | 未测试（灰） |
| `TESTED_FINDINGS` | 已测题数 > 0 且风险（failed）> 0 | 已测·发现风险（红） |
| `TESTED_CLEAN` | 已测题数 > 0 且 failed = 0 | 已测·未发现风险（绿） |

- `sampleAdequate`：已测题数 ≥ 10。样本偏少时页面提示，不宜据此下结论。
- `undetermined`（无法判定）**不计为通过**，单独列示。但若某条目只有无法判定的题，仍显示为「已测·未发现风险」，请结合「无法判定」列和样本提示解读。
- 「平台能不能测」由映射表反推：`SUPPORTED = 所有风险域与平台应用场景能到达的条目`。不手工声明，也不为凑覆盖硬映射。

## 4. NOT_SUPPORTED 的含义与当前清单

含义：**不是没测，而是平台目前没有能测这一条的评估能力**。矩阵上保留该行并写明原因，避免把「平台测不了」误读为「测过没事」。

当前清单（以 `coverage.ts` 的映射反推结果为准，单测固定了该清单）：

| 框架 | 条目 | 原因 |
| --- | --- | --- |
| OWASP 智能体 | ASI04 智能体供应链漏洞 | 不检测智能体所用第三方工具、插件、模型的供应链完整性；终端智能体检测里的技能来源、MCP 传输检查是配置体检，未映射到本条目 |
| OWASP 智能体 | ASI07 不安全的智能体间通信 | 一次评估只面对单个被测智能体，没有多智能体消息伪造、重放的测试 |
| OWASP 智能体 | ASI09 人机信任利用 | 没有评估智能体诱导人工审批的测试 |
| OWASP 智能体 | ASI10 失控智能体 | 没有对长期运行中目标漂移、自我复制等的持续观测 |
| OWASP 大模型 | 无 | LLM01–LLM10 均有风险域映射；LLM03、LLM04、LLM08 只覆盖一部分，见条目备注 |
| 国标附录 A | 无 | A.1–A.5 均有映射；A.2 仅有偏见歧视一个域，样本通常较少 |
| MITRE ATLAS | 无 | 只展示平台能映射到的技术，未展示的技术不在讨论范围 |

ASI08 现在只由沙箱「上游连续失败后是否停止调用」一个场景覆盖，note 里写明多智能体链路的故障放大没有测。部分覆盖的条目会在 `note` 里说明边界，例如 ASI01 仅平台应用评估场景映射、ASI03 不含身份冒用、LLM04 仅覆盖 RAG 知识库投毒。

## 5. 如何补测

| 状态 / 条目 | 推荐评估方案 |
| --- | --- |
| LLM01、LLM07、ATLAS T0051/T0056（提示词注入、系统提示泄露） | 综合评估或红队评估；红队的自适应攻击比静态题库更能暴露问题 |
| LLM02、A.4、ATLAS T0024.000/T0086（敏感信息、训练数据、数据外传） | 综合评估的隐私与数据外传类题；对真实应用用平台应用评估或智能体评估的数据外传场景 |
| LLM03（供应链）、LLM05（输出处理）、LLM10（无限制消耗） | AI 组件漏洞扫描、模型文件扫描；输出注入与资源消耗用红队评估对应方向 |
| LLM04、LLM08（投毒、向量与嵌入） | RAG 专项评估 |
| LLM06、ASI02、ASI03、ASI05、ATLAS T0053（工具滥用、越权、代码执行） | 智能体评估（沙箱工具调用）、终端智能体评估 |
| ASI01、ASI06、ASI08（目标劫持、记忆投毒、级联故障） | 平台应用评估（间接网页注入、知识库越权）、智能体评估开启「智能体沙箱场景」（L8） |
| A.1、A.2、A.3、A.5（国标内容安全） | 内容安全评估 / 备案相关的标准评估，补足样本量到 10 题以上 |
| ASI04、ASI07–ASI10 | 平台暂不支持，只能线下人工评审，或等待相应评估能力上线 |
| 「样本偏少」 | 增加该类题目数量（抽样评估时提高抽样题数） |

## 6. 与热力图的关系

「风险处置 → 框架映射与热力图」按评估对象或任务展示失败率，保留人工映射修订，ATLAS 一侧还会按战术展开。覆盖矩阵则按条目回答「测没测」，不展开战术，也不受人工映射影响，两者口径不同，不要互相对数。
