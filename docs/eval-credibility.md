# 评测可信度说明

本文说明平台为「评测结果可信度」提供的几项能力，以及如何正确阅读这些数字。所有能力都只**新增展示字段**，不改变评分、判定和计数的计算逻辑，也不改变门禁的判定逻辑。

## 为什么需要

自动判定（规则、分类器、评判模型）算出的「失败率」并不是一个精确值：

- 样本少时，同一个模型重跑一次，失败率可能差出很多。
- 不同判定器看同一批回答，结论可能差一个数量级。
- 判定器会被回答的表述方式影响。

所以一个孤零零的百分比不足以支撑结论，需要同时看到**样本量、波动范围，以及判定器本身靠不靠谱**。

## 一、发现风险比例与置信区间

任务详情「结果可信度」卡片、评估报告「执行概览」均给出：

| 项目 | 含义 |
| --- | --- |
| 发现风险比例（失败率） | 失败条数 ÷ 有效样本量 |
| 95% 置信区间 | 在当前样本量下，真实失败率有 95% 的把握落在该范围内。样本越少，区间越宽 |
| 有效样本量 | 通过 + 发现风险 + 未判定。执行异常（没拿到有效回答）不进入分母 |
| 未判定 | 判定器无法给出结论的回答，**不计为通过**，单独列出占比 |

置信区间采用威尔逊区间（对小样本和接近 0%/100% 的比例比常见的正态近似更可靠），在 `apps/api/src/lib/eval-statistics.ts` 中以纯函数实现，没有第三方统计依赖。

### 小样本警告

| 有效样本量 | 提示 |
| --- | --- |
| 0 | 暂无有效样本，无法给出比例 |
| 少于 10 | 样本过少，仅供参考，不宜据此下结论 |
| 少于 30 | 样本偏少，置信区间较宽，结论请谨慎使用 |
| 30 及以上 | 不提示 |

另外，未判定占比达到 20% 及以上时会追加提示：判定器对较多回答无法给出结论，失败率可能被低估。

### 怎么读

- 失败率 30%，区间 22%~40%：真实值大概率在 22% 到 40% 之间，不要把 30% 当作精确值。
- 区间很宽时，优先增加样本量，而不是纠结点估计值。
- 未判定很多时，说明「通过」的那部分并不等于安全，应先补充判定或人工复核。

接口字段：任务详情与任务列表的 `statistics`（`sampleSize`、`failRate`、`failRateLower`、`failRateUpper`、`unknownCount`、`unknownRate`、`warningCodes`、`warnings`），报告 `summary.statistics`。

## 二、任务对比的「差异是否可信」

多模型对比页与回归对比页，会对失败率的变化给出提示：

- 两次的 95% 置信区间**重叠**：提示「差异未超出统计波动」，暂不能认为两者有真实差别。
- 区间**不重叠**：提示「差异超出统计波动，大概率是真实变化」。
- 任一侧样本少于 10：附加「样本过少」的谨慎提示；任一侧无样本：提示「样本不足」。

区间重叠法偏保守（区间略有重叠时，严格的假设检验有时仍能判出显著差异），它的用途是防止把随机波动当作结论，不等同于正式的显著性检验。

## 三、判定可信度（人工校准）

任务详情「判定可信度」卡片回答一个问题：**自动判定和人工结论一致吗**。

数据来源是已有的风险发现人工复核（风险样本页的「保存复核结论」），不新增表：

- 确认风险、接受风险 → 人工认为**有风险**
- 误报 → 人工认为**无风险**
- 未复核、待人工复核 → 不参与计算，计入「待复核」

与自动判定对照后得到：

| 指标 | 含义 |
| --- | --- |
| 人工已复核样本 | 参与计算的样本数 |
| 判定与人工一致率 | 判定和人工结论相同的比例，带区间 |
| 一致性系数 | 扣除「碰巧一致」后的一致程度（学术上称 Cohen kappa）。小于 0.2 很弱，0.4~0.6 中等，0.6~0.8 较强，大于 0.8 几乎一致 |
| 漏报 | 判定为通过，但人工认为有风险。风险被放过，最需要警惕 |
| 误报 | 判定为有风险，但人工认为无风险。会浪费整改精力 |

**数据不足时不硬算**：人工已复核样本少于 10 条时，接口返回 `status: INSUFFICIENT` 与「数据不足」说明，不输出一致率与系数。人工结论几乎全部同类（例如只复核了判失败的样本且全部确认）时，一致性系数无法定义，同样会说明原因。

接口：`GET /api/eval-tasks/:id/judge-calibration`，权限沿用 `eval_task:read`。

### 随机抽检

「随机抽检」按种子随机抽取 N 条（默认 20，最多 200）尚未人工复核的发现，相同种子得到相同清单，便于多人分工与复现。清单提供跳转到「风险样本」页的链接，复核操作复用现有入口，没有新增流程。

接口：`GET /api/eval-tasks/:id/judge-calibration/sample?size=&seed=`。

抽检建议：

1. 样本不要只挑「看着有问题」的，随机抽才能代表整体。
2. 至少复核 30 条以上，再看一致率与区间。
3. 一致率低或漏报多时，不要直接采信自动失败率，应调整判定规则或评判模型后复测。

### 当前局限

风险样本页只列出判定为失败的结果，因此现有复核入口天然只能校出「误报」方向；「漏报」需要对判定为通过的结果做人工复核，当前尚无该入口，计算逻辑已支持，待后续补充。

## 四、门禁

门禁判定逻辑不变。门禁结果的 `sampleSize`、`sampleWarning` 仅用于展示：当触发门禁的任务样本偏少时，门禁页会在判定结果下提示样本量警告，提醒「通过」或「不通过」所依据的数据较少。

## 五、报告中的体现

Markdown/PDF/HTML 报告的结论部分会增加一段「统计可信度」，格式如下：

> 发现风险比例 30.0%（样本量 100，95% 置信区间 21.9% ~ 39.6%），未判定 10 条（占 10.0%，不计为通过）。置信区间表示：在当前样本量下，真实的风险比例有 95% 的把握落在该范围内，样本越少区间越宽。

执行概览表中同时增加「发现风险比例（95% 置信区间）」与「未判定（不计为通过）」两行。
