# 标准条款主表与三条测评线

更新：2026-11-13。代码在 `packages/shared/src/standards/`，单测在 `apps/api/test/standards-catalog.test.ts`。

## 一、为什么要有主表

此前的标准映射散落在 `reports/compliance-mapping.ts`、`frameworks/coverage.ts`、样本 `refs`、五维度表、`reports/labels.ts` 等处。层级不统一，有的按风险域，有的按风险面、场景、样本；而且一直挂着「待复核」，没有人复核。

结果是报告里出现了三类问题：
- 无出处的条款，例如「GB/T 45654 智能体检测项 ①②④」；
- 硬凑的映射，例如工具越权映射到附录 A.4，提示注入挂到附录 B；
- 所有报告共用同一份依据清单。

现在统一为一张主表：

```
依据（bases.ts） → 条款（clauses-*.ts） → 结果折算（reports/standard-clauses.ts） → 条款结论（catalog.ts evaluateClause） → 报告
```

主表里查不到的映射，报告里一律不出现。

## 二、三条测评线及主依据

| 测评线 | 主依据 | 条款文件 | 结论口径 |
|---|---|---|---|
| 大模型内容安全 `content` | GB/T 45654-2025：附录 A 31 项、附录 B 方法、正文模型安全与安全措施；辅以 GB 45438 标识、拟人化办法 | `clauses-content.ts` | 风险类（附录 A）：发现风险 / 未发现风险 / 样本不足 / 未测。方法与措施类：符合 / 不符合 / 证据不足 / 未测 / 不适用 |
| 智能体应用 `agent` | 在研强制性国标《智能体应用安全基本要求》（20263116-Q-252，非现行）公示的 8 项技术内容 | `clauses-agent.ts` | 符合 / 不符合 / 证据不足 / 未测 |
| 终端智能体 `endpoint` | TC260-PG-20266A《智能体部署使用安全指引》附录 A 31 项检查清单，加上述 8 项 | `clauses-endpoint.ts` | 符合 / 不符合 / 未检 / 不适用（需人工填报） |

国际框架（OWASP LLM 2025、OWASP Agentic 2026、MITRE ATLAS）只作「对照参考」，不进评估依据，见 `catalog.ts` 的 `LINE_BASES.reference`。

报告依据说明固定写法见 `LINE_BASIS_STATEMENT`。智能体线和终端线必须写明「目前尚无现行专项国家标准，参照在研强制性国家标准（非现行）」。

## 四、三维分类

| 维度 | 用途 | 枚举 |
|---|---|---|
| 攻击手法 `AttackVector` | 组织攻击库 | 直接请求、越狱与规避话术、间接注入、工具投毒、记忆和配置投毒、多步拆分、任务诱导的过度操作、供应链、配置缺陷 |
| 资产与通道 `AssetChannel` | 说明攻击从哪里进来 | 用户输入、多轮对话、文档、代码注释、依赖、网页、工具描述、工具返回、知识库、记忆文件、智能体配置、CI 配置、图片 |
| **危害后果** | **唯一对接标准的维度** | 内容线是附录 A 31 项；智能体和终端线是 `AgentHarm` 14 项 |

旧分类（风险面、攻击招式、终端风险类型、运行态 vector/harm、MCP 攻击类、平台应用场景、风险域）一律经 `taxonomy.ts` 的 `legacy*` 函数折算，**不再新增平行的分类表**。

## 五、各测评线必须遵守的契约

1. **新样本、新题目在元数据里写 `clauseIds`**（条款 id 数组，例如 `["gbt45654.A.2.e"]`、`["agentsec.high-risk-hitl"]`）。报告按 `reports/standard-clauses.ts` 的优先级归条款：
   1. 显式 `clauseIds`；
   2. 类别为附录 A 小项编号；
   3. 风险域经危害后果折算。
2. **新增条款只改 `clauses-*.ts`**，并跑 `standards-catalog.test.ts`。自检要求：
   - id 不重复；
   - 依据存在且不是国际框架；
   - 写 `sourceRef`；
   - 能力不是 `covered` 时写清边界。
3. **方法类条款**（合格率、拒答率、题库规模）由各线按阈值算好后，以 `manualVerdict` 传入 `evaluateClause`，不要用计数推算。
4. **不得**在报告里写「符合性」「合规认证」。标题统一经 `neutralizeCertificationWording`。出具门槛：
   - 有效判定为 0 不出报告；
   - 少于 10 项标「预评估」。
5. **不再给 0–100 综合分**。结论以条款对照和发现率为准。

- 终端报告走 `packages/shared/src/endpoint-report-html.ts` 专用版式，条款对照由终端线自己渲染。
