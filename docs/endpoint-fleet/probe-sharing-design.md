# 鉴盾 × 智能体安全平台 · 终端探针共用设计（v1，2026-10-22）

> 状态：设计稿，待实现。范围：同一份终端探针（`agent-platform-collector`），在「只有鉴盾」「只有智能体安全平台」「两者都有」三种部署下怎么工作。
>
> **2026-10-23 更新**：下文设计时曾规划「鉴盾侧真机测评必须由另一位终端管理员审批」，实际已调整为**管理员发起即下发，不再审批**（升级前遗留的待批准任务保留批准接口）；Windows 真机测评也不再按系统一刀切，以终端上报的测评执行器为准。以 `admin-api.md`、`deployment-guide.md` 的现行描述为准，下文中的「审批」相关表述保留为原始设计记录。

## 一、先说清楚几个事实（读代码得出，不是推测）

1. 采集器与服务端之间是一套固定的 HTTP 协议 `/agent/v1/*`：`endpoints/register`、`endpoints/heartbeat`、`probe-reports`、`behavior-reports`、`policy`、`eval-jobs`（拉任务→ack→started→result）等。Bearer 令牌、证书钉扎 HTTPS、接入码一次性注册。
2. 采集器**不关心对端是谁**，只认协议、地址和证书钉扎。所以**服务端是可替换的**：谁实现了这套协议的最小子集，谁就能当探针的"主人"。
3. 测评相关的"手脚"（`eval_job_cycle`、`eval-runner`、hookd 测评模式）已经在采集器里，**默认关闭**，由 `collector.json` 的 `eval_jobs_enabled` 和本机 `eval-registry.json` 控制。
4. 采集器里另有大量智能体安全平台**专有**的管控能力（受管配置、凭据下发、模型中继、网关、`managed-*`、升级通道），鉴盾**不需要也不应该**实现。

## 二、核心原则

**一台终端，同一时刻，只听一个"服务端"。** 这是最简单、最安全的规则：令牌、审批、审计、升级、责任边界都只有一个来源，不会出现两个平台同时指挥一台电脑的权限冲突。

- 终端的"主人"由**注册时用的接入码**决定：接入码是谁签发的，终端就注册到谁。
- 采集器本地状态里记录 `server_kind`（`agentshield` | `jiandun`）和 `server_url`、证书指纹。
- 要换主人，必须先**解除绑定**（卸载或 `unbind`），再用新服务端的接入码重新注册。不支持"双写"。

## 三、三种部署情况

### 情况 1：探针 + 鉴盾（独立版，客户没买智能体安全平台）

```
鉴盾  ◀── /agent/v1/*（最小子集）──  探针（server_kind=jiandun）
```

- 探针用**鉴盾签发的接入码**向鉴盾注册。
- 鉴盾实现最小协议：`register`、`heartbeat`、`probe-reports`（配置体检数据）、`eval-jobs`（下发测评）、`policy`（返回空策略）。其余管控类端点一律不实现并明确返回"此服务端不支持该能力"。
- 能力：终端清单、配置体检、真机测评（管理员发起即下发；原设计含审批，已取消）。**没有**：行为审计、受管配置、凭据下发、模型中继、网关联动。
- 界面：鉴盾自己的「终端」页面（终端清单、测评任务、接入终端）。

### 情况 2：探针 + 智能体安全平台（现状，不动）

```
智能体安全平台 ◀── /agent/v1/* ──  探针（server_kind=agentshield）
```

- 完全保持现状，全部管控能力可用。
- 如果客户同时有鉴盾，走情况 3。

### 情况 3：探针 + 鉴盾 + 智能体安全平台（联动）

两条路径都合理，我们**只做第一条**：

**路径 A（默认，做）：探针归智能体安全平台，鉴盾通过连接器复用**
```
鉴盾 ──HMAC连接器──▶ 智能体安全平台 ◀── /agent/v1/* ── 探针（server_kind=agentshield）
```
- 这就是现在的结构。鉴盾在 `server_kind=agentshield` 的终端上发起测评时，经连接器让智能体安全平台下发任务。
- 这样"测评由谁审批"是智能体安全平台说了算，符合"终端管理员统一管终端"的企业习惯。

**路径 B（不做，仅预留）：探针同时听两个服务端**
- 需要采集器支持多服务端并发、各自令牌与队列、任务冲突仲裁，复杂度和风险都高，且没有明确客户需求。**明确不做**，在设计里留接口位但不实现。

### 情况之间的迁移

| 迁移 | 怎么做 |
|---|---|
| 独立版（鉴盾）→ 联动版（智能体安全平台） | 客户后来采购了智能体安全平台：在终端上 `unbind`，用智能体安全平台的接入码重新注册；鉴盾侧该终端标记为"已迁移"，历史测评记录保留，新测评走路径 A |
| 联动版 → 独立版 | 反向同理 |
| 鉴盾里「复用」的终端与「自管」的终端 | 终端清单里每台终端带标签：来源 = `智能体安全平台（复用）` / `鉴盾（自管）`，决定测评走连接器还是直连 |

## 四、鉴盾侧要新增什么（第一期）

1. **终端接入服务**（新模块 `endpoint-fleet`）：
   - 接入码：创建（有效期、数量上限、用途标签）、列出、撤销；只存哈希，明文只显示一次。
   - 终端注册：校验接入码 → 登记终端（machine_id、hostname、os、owner、已装智能体及版本）→ 签发端点令牌（只存哈希）→ 返回最小配置。
   - 心跳：在线状态、能力（`eval_runner` 版本）、健康。
   - 配置体检上报：接收 `probe-reports`，落库，供「配置体检」使用。
   - 令牌轮换、吊销、重注册。
2. **测评任务下发**：沿用采集器已有的 `eval-jobs` 协议（拉取→校验 checksum→ack→started→result）；鉴盾侧负责审批、签发 checksum、接收结果、与现有 `endpoint-evals` 的结果入库逻辑对接（即把"AgentShield 回调"和"终端直连回传"统一成同一条入库路径）。
3. **审批**：真机测评必须经**鉴盾侧的终端管理员**审批（沿用现有"需终端管理员审批"文案与权限，新增 `endpoint:approve` 权限）。
4. **界面**：评估中心下新增「终端」页（清单、接入码、待审批任务、任务记录）；现有「接入终端」引导页并入，按情况 1 / 3 分别展示。
5. **安全**：令牌/接入码只存哈希；全部端点鉴权在读 body 之前；限流；请求体限长；审计日志；服务端**绝不**对请求中的 URL/路径发起访问；隐私红线（不接收源码、对话正文）。

## 五、探针侧要改什么（第二期，在 AgentShield 仓库）

1. 采集器新增 `server_kind` 配置与状态字段；注册时记录；**重注册到不同 kind 前必须先 unbind**。
2. 对 `jiandun` 类服务端，采集器**只启用最小周期**：注册、心跳、`probe-reports`、`eval-jobs`；其余管控周期（managed-*、credential-delivery、upgrade 等）自动关闭，不依赖服务端 404 来"碰运气"。
3. 打**独立发布包**（沿用现有 `tools/install-enterprise-linux.sh` 等安装器和受信 manifest 机制），包名与服务名保持 `agent-platform-collector`，安装命令多一个 `--server-kind jiandun`。
4. 升级通道：独立版**不走** AgentShield 的自动升级（它依赖其发布服务）；升级由客户用同一安装器 `upgrade` 手动或经 EDR 下发。
5. 文档：安装器说明、情况 1/2/3 的差异、迁移步骤。

## 六、分期

| 期 | 范围 | 验收 |
|---|---|---|
| 第一期 | 鉴盾侧终端接入服务（最小 `/agent/v1/*`）、接入码、终端清单、配置体检、测评任务与审批、界面。探针侧**用现有采集器 + 配置里手工指向鉴盾**先联调，不改探针代码（若协议有差异再记下来） | Linux 终端用鉴盾接入码接入并完成一次配置体检；协议测试覆盖 |
| 第二期 | 探针侧 `server_kind`、最小周期、独立包；真机测评（Linux）端到端；Windows 打通现有问题 | Linux 真机测评端到端；包校验；解绑/迁移 |
| 第三期 | Windows、macOS 对齐；证书/升级/EDR 分发；联合运营体验（复用终端的标签、迁移向导） | Windows 真机测评；迁移演练 |

## 七、风险与待办

1. **Windows 真机测评现网尚未完全打通**（模型出口环境变量、执行器版本），第二期必须先解决。
2. **协议兼容的真实性**：第一期要用真实采集器去连鉴盾，才能确认"最小子集"到底够不够；可能发现采集器对某些响应字段有隐含依赖。预留一轮对齐修复。
3. 鉴盾和智能体安全平台**同时部署在同一台服务器**时，端口、证书、接入码前缀要区分，避免客户把接入码填错对象；鉴盾接入码以 `jdc_` 开头，智能体安全平台接入码为无前缀的 64 位十六进制；采集器 `enroll --server-kind` 在发请求前校验前缀与类型一致（已在 AgentShield 50ba8d3a 实现）。
4. 终端上跑真实智能体属高危操作，所有新增端点需要**独立安全评审**（令牌、审批绕过、任务注入、路径穿越）。
5. 独立版与联动版共用一个包名，客户可能在同一台终端误装两次；安装器必须检测已绑定的 `server_kind` 并拒绝覆盖。
