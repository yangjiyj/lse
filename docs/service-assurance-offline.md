# AI 服务安全核验离线运行手册

本文面向离线部署管理员，说明“AI 服务安全核验”在断网环境中的安装后检查、三种核验模式、诊断和回滚边界。客户菜单名称为“服务安全核验”。

## 1. 能力范围

平台提供以下 3 种模式：

| 客户界面名称 | 默认状态 | 适用输入 | 结果边界 |
| --- | --- | --- | --- |
| 安全检查 | 默认启用 | 已授权的服务地址、接口说明 | 以非破坏方式检查暴露面和配置；只有配置命中或充分证据才能形成正式风险 |
| 组件清单核验 | 默认启用 | CycloneDX 或 SPDX 组件清单 | 使用离线漏洞库做组件和精确版本判断；只有组件名称时显示“疑似组件、待核验线索” |
| 授权深度核验 | 按需启用 | 已明确授权的 OpenAPI 服务 | 在固定请求预算内进行主动验证；未确认授权时拒绝启动 |

严重度、证据可信度和整改优先级是 3 个独立字段。未知严重度保持未知，不自动归为中危。

当执行组件失败、规则基线过期、漏洞库未就绪或可选模式未启动时，页面和报告会显示“核验未完成”或“覆盖不完整”。这类状态不能解释为“未发现风险”。

## 2. 离线制品与信任边界

正式离线包包含固定版本的应用镜像、核验镜像、规则基线和漏洞库，并提供以下校验文件：

- `manifest.json` 与 `manifest.sig`：离线包清单及其签名。
- `image-lock.json`：镜像引用与实际镜像内容摘要。
- `checksums.sha256`：包内文件摘要。
- `service-assurance/trust/`：规则基线和漏洞库的签名、公钥。
- `service-assurance/vulndb/LICENSES.md`：漏洞库来源与许可证说明。

安装和升级会先校验签名、摘要和镜像锁。运行时不会下载未知模板、规则或漏洞库，也不会使用 `latest` 镜像标签。私钥不在离线包内。

核验执行组件不挂载 Docker Socket、平台数据库、队列地址或平台 `.env`，并采用非 root、只读根文件系统、最小权限和资源上限。它们只通过内部控制网络接收任务，通过受限执行网络访问已经授权的目标。

## 3. 安装后检查

安装完成后执行：

```bash
sudo lsectl status
```

状态输出应包含平台核心服务以及默认启用的“安全检查”和“组件清单核验”执行服务。随后登录平台，在“服务安全核验”页面查看三种模式的就绪状态。

按需启用授权深度核验：

```bash
sudo lsectl deep-start
```

停止可选模式：

```bash
sudo lsectl deep-stop
```

停止可选模式不会删除历史运行、正式风险、人工复核或审计记录。

## 4. 断网运行

默认两种模式完全使用包内规则和漏洞库，可以在断开公网后启动和重启。授权深度核验同样不依赖公网更新，但目标本身必须位于已批准的可达范围内。

断网验收至少检查：

1. 重启 Docker 和平台后，核心服务自动恢复。
2. 安全检查、组件清单核验显示已就绪。
3. 显式启动后，授权深度核验显示已就绪。
4. 受控正样本、负样本和缺版本样本得到与联网前一致的结论。
5. 没有运行时规则下载、漏洞库更新或外部遥测请求。

不要扫描未经授权的公网目标。客户提供的授权范围、域名、解析地址、实际连接 IP、CIDR 和重定向目标都会在执行前重新校验。

## 5. 诊断

生成脱敏诊断包：

```bash
sudo lsectl diagnose
```

诊断包包含服务状态、健康检查和最近日志，不应包含管理员密码、Token、API 密钥、Cookie 或其他长期凭据。提交诊断包前仍应按客户数据管理制度复核文件内容。

常见状态：

- **未就绪：** 对应执行组件尚未启动或基线校验失败。
- **覆盖不完整：** 本次核验只有部分步骤完成，必须处理失败项后复测。
- **规则基线过期：** 当前结果只能作为有限覆盖证据，应更新为已审核的离线基线后重新执行。
- **待人工复核：** 证据已保留，但尚未形成最终处置结论。

更多排查命令见 [离线故障排查](./offline-troubleshooting.md)。

## 6. 升级与回滚

升级前会备份数据库和 `.env`。任一备份为空或失败，升级立即中止。升级完成后，安装目录下的 `rollback-snapshots/` 保存旧 Compose 文件和旧应用镜像内容摘要。

列出可用回滚点：

```bash
sudo lsectl rollback --list
```

回滚到最新快照：

```bash
sudo lsectl rollback
```

回滚到指定快照：

```bash
sudo lsectl rollback --to YYYYMMDD-HHMMSS
```

回滚只恢复旧应用镜像和旧 Compose 配置，**不恢复旧数据库**。新建的数据表、历史运行、正式风险、原始证据、人工复核和审计记录继续保留。回滚前还会再次备份当前数据库和 `.env`；备份失败时不会切换应用。

回滚不会删除数据卷、日志卷或历史证据。若旧应用无法在保留的新数据库结构上健康启动，回滚会明确失败并保留诊断信息，不能通过删除新表或历史数据绕过。

完整升级步骤见 [离线部署升级与卸载手册](./offline-upgrade-uninstall-manual.md)。

## 7. 验收记录

正式交付应分别保存以下证据，不能只保留一个“健康”结论：

- 全新安装、重启自启和断网重启记录。
- N-1 安装包摘要、候选安装包摘要和升级备份记录。
- 三种模式的正样本、负样本、覆盖不完整和规则过期结果。
- `image-lock.json` 与实际镜像内容摘要的比对结果。
- 诊断哨兵在 API、数据库、日志、执行组件、报告和诊断包中的零明文检查。
- 故障注入、恢复、回滚、旧证据查询和再次升级记录。

缺少任一项时，只能报告对应项目“未验证”或“未通过”，不能把安装成功等同于整个平台可交付。
