# LSE 1.0.1 模型配置一致性修复

## 发布范围

- 基线：`main@ad2697883a70ba03b041fe0db351a9877c341b30`
- 版本：`1.0.1`
- 架构：`linux/amd64`
- 最终提交、镜像 ID、镜像摘要、安装包位置及 SHA-256 以发布验收记录为准。

## 修复内容

- 删除模型时同步清理 `redteam.config` 与 `agent_eval.config` 中的角色引用，并在删除审计中记录被清理字段。
- 正式数据库迁移幂等修复旧版本遗留的孤儿引用；只清空无对应模型记录的引用，保留有效配置与历史业务数据，并追加系统升级审计。
- 接口地址、模型标识、密钥或其他实际连接参数变化后，旧连接测试状态失效；仅修改显示名称或重复保存相同配置时保留测试状态。
- 设置页测试、保存、候选刷新和页面重开均以已保存配置为准；留空密钥表示保留已有密钥，浏览器自动填充不再污染模型标识字段。
- 自主红队候选会剔除已删除、停用、不完整或与评估对象同接口同模型的记录，并区分未配置、配置不完整、停用、加载失败、测试失败和独立性冲突。
- 两个 `MODEL` 评估对象加一个 `JUDGE` 独立模型会显示三个模型记录；`JUDGE` 不计入评估对象数量。

## 安装与升级

```bash
sha256sum -c lse-x86-offline-1.0.1-<提交>.run.sha256
sudo bash lse-x86-offline-1.0.1-<提交>.run
sudo lsectl status
```

升级脚本会先备份数据库和部署文件，再加载锁定镜像、执行 Prisma 正式迁移并重建前后端。`.env`、许可证、密钥、历史任务和报告保持不变。

## 回滚

```bash
sudo bash lse-x86-offline-1.0.1-<提交>.run --rollback
```

也可执行升级输出中记录的回滚命令。应用镜像和部署文件回到升级前快照；数据库采用向前兼容策略，不删除迁移记录或审计记录。需要恢复升级前数据库内容时，使用升级前 `pg_dump` 备份在维护窗口单独恢复。
