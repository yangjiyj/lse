# LSE 1.0.8 安装、升级、备份、恢复与回滚

验证范围：Ubuntu 24.04 x86_64，systemd，root/sudo。建议 4 核/8 GB、至少 35 GB 空闲磁盘；模型推理需访问既有授权模型接口，安装包不含模型权重。

## 安装和升级

将 .run 和 .run.sha256 放同一目录，执行 `sha256sum -c <文件>.run.sha256`，再执行 `sudo bash <文件>.run`。首次安装生成随机口令；已有 `/opt/lse/platform/.env` 时保留配置并升级。安装期间无需访问公网软件源和镜像仓库。

实际访问地址以安装输出为准，端口从 HTTP 8090/HTTPS 10443 开始选择空闲端口。管理员初始口令只保存在 `/opt/lse/platform/INITIAL_CREDENTIALS.txt`。不要将该文件放入分发包。

安装后使用 `sudo lsectl status`，访问 `/api/version` 核对 1.0.8 与源码提交。模型文件可放 `/opt/lse/models` 或设置 `MODEL_SCAN_HOST_DIR`。

`CONFIG_TEMPLATE.env` 仅作配置参考，实际新安装配置由安装器生成；已有配置不会被模板覆盖。可选集成配置：`LSE_AGENT_GATEWAY_ORIGINS`、`LSE_BATCH_CALLBACK_SECRET/KEY_ID`；租户绑定文件放部署目录 `integrations/tenant-bindings.json`，只授予应用 UID 1000 读取并设 0600。客户受信 CA 可放同目录并设置容器路径 `NODE_EXTRA_CA_CERTS`。配置现有网关地址和凭据即可，无需修改、升级或重启 JJDGuard。

## 备份

`sudo lsectl backup` 生成数据库备份。完整备份另需停写并保存 `.env`、`INITIAL_CREDENTIALS.txt`、部署文件、`integrations/`、`backups/` 和所有持久卷（pgdata、valkeydata、caddy_data、model_scan_uploads）。当前镜像须 `docker save` 保全。

## 恢复

完整恢复前停止 API/worker/Web，并为待替换状态另做备份。恢复与备份配套的部署文件和镜像、`.env`、集成文件及持久卷，然后启动数据库和队列。数据库逻辑备份可在隔离空库中用 `pg_restore --exit-on-error --no-owner --no-acl` 恢复；SQL 备份用 `psql -v ON_ERROR_STOP=1`。生产整库替换须确认新增数据的处理范围，禁止边写边恢复。

冷备卷恢复须在相关容器停止时解压，保留原 UID/GID 和文件权限。PostgreSQL 冷备仅用于同一数据库大版本、兼容镜像。

## 应用回滚

升级前安装器保存 `rollback-snapshots/<时间>/` 与数据库备份。执行 `sudo lsectl rollback`，或指定已验证的快照目录；回滚恢复旧 Compose 和镜像，数据库保持向前兼容，不删除新表和 AGENT 枚举。本次五项迁移是增加项，已使用新功能的数据不能被旧版完整解释；遇到兼容性问题使用升级前完整备份恢复，并先处理备份后的新增数据。

## 运维和卸载

`sudo lsectl diagnose` 生成脱敏诊断包。先检查磁盘、Docker/systemd、`lsectl status`、迁移及 `/api/health`，再检查 `/api/version` 和授权模型接口。HTTPS 自签 CA 需要客户端信任；不能用 TLS 错误或 UNKNOWN 作为评估通过。

停服务执行部署目录 `stop.sh`。卸载使用 `uninstall.sh` 并按其提示操作；先备份，默认不删除持久数据。只有明确要清除隔离测试数据时才使用 purge 模式，生产数据不做未经确认的清理。
